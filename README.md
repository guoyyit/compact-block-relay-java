# compact-block-relay-java

区块高效传播（Compact Block Relay，类 BIP152 思路）的纯进程内模拟实现。
节点之间通过本地回环网络（`LoopbackNetwork`）交互，不依赖外部组件或真实网络；
每个节点维护自己的本地交易池，新区块优先以“区块头 + 每笔交易的短标识”传播，
仅缺失交易通过合并请求补齐，异常情况下安全回退到完整区块传输。

## 协议交互流程

1. **紧凑通知**：发送方对区块内每个 txid 计算 64 位短标识
   `SipHash-2-4(k0, k1, txid)`（`crypto/SipHash.java`），发送
   `AnnounceMessage`：区块头（含全部 txid 声明、随机数）+ 短标识列表 + SipHash 密钥。
2. **本地重建**：接收方（`relay/RelayNode.java`）用本地交易池按短标识匹配交易并填入槽位。
   - 每个短标识命中唯一候选：直接采用。
   - 命中多个候选（短标识碰撞，存在歧义）：**不猜测**，立即请求完整区块。
   - 未命中：记为缺失。
3. **缺失合并补齐**：所有缺失下标合并为**一次** `TxRequestMessage`（按下标请求，避免短标识歧义），
   发送方以一次 `TxResponseMessage` 批量返回；请求超时按 `max-request-retries` 重试。
4. **重建中本地新交易回填**：重建会话进行期间，本地新到达交易会检查**每个**在途会话的未填充槽位：
   - 仅当区块头声明的 txid 与该槽位短标识校验**同时一致**时才填入；
   - 已填入的槽位立即移出请求集合，任何在途请求超时重试都不会再次请求它，同一槽位至多请求一次；
   - 回填后会话全部槽位齐备时**立即**完成并上链，不等待在途补齐响应或其超时；之后迟到的
     `TxResponseMessage` 因会话已终止被安全丢弃，不重复应用交易或区块；
   - 同一笔新交易可同时填入多个不同区块（含同高度竞争区块）的在途会话，各会话独立判定互不影响；
   - 若新交易对应短标识在本地交易池中存在多个候选（碰撞歧义），保持既有规则：**不猜测**，
     该会话回退完整区块。
5. **逐笔校验**：重建完成后逐笔校验
   - 交易内容哈希等于其 txid（`SHA-256(data)`）；
   - 交易 txid 与区块头声明的对应下标 txid 完全一致；
   - 交易短标识与通知中的短标识一致。
   任一不一致立即回退完整区块，接收方永远不会接受交易内容错误的区块。
6. **完整区块回退**：重建超时、补齐请求超时/失败、碰撞歧义、内容校验失败都会发送
   `BlockRequestMessage`，发送方回 `BlockResponseMessage`。完整区块同样经过全量校验后才上链。
   - 回退请求具备**独立超时**（`fallback-request-timeout-ms`）与**有限重试**
     （`max-fallback-retries`，不含首次请求）；请求/响应丢失或对端暂时不可用会自动重试。
   - 回退重试耗尽仍无响应时，释放该区块的会话占位、回退占位与去重窗口记录，区块**不被当作
     已处理**；随后任意对端重新发送的同一区块通知会被重新接纳（计入
     `reacceptedAnnouncements`），重新进入重建或回退，数据可用时最终上链。
   - 回退进行中重复到达的同一区块通知不会引发额外回退请求；区块成功后或重试期间，迟到的
     补齐响应、完整区块响应与重复通知一律安全丢弃，区块最终只应用一次。
   - 已接受区块的去重与重启恢复语义不变：仅完整上链的区块持久化，回退耗尽状态只存在于内存。

## 安全与一致性保证

- **碰撞安全**：64 位短标识在带宽（仅为完整 256 位 txid 的 1/4）与碰撞概率之间取舍；
  碰撞歧义或恶意/错误响应一律触发完整区块回退。
- **去重与迟到消息**：每个节点用单线程事件循环串行处理全部消息、本地调用与超时事件；
  会话终止或区块已接受后，重复/迟到的交易响应与完整区块响应全部丢弃。
  完整区块回退路径与紧凑路径并发发生时，结果由事件循环顺序确定，区块只应用一次。
- **并发通知收敛**：同一区块的多份通知只建立一个重建会话、只发一批补齐请求；
  重建中到达的新交易进入交易池并回填在途会话（见协议流程第 4 步），到达的新区块通知按链序正常处理。
- **过期/孤儿通知**：高度不高于当前链尖的通知直接丢弃；父块缺失的通知/完整块进入有界孤儿队列，
  父块接上后按序重放。
- **增长有界**：交易池（`max-mempool`，FIFO 淘汰）、已见区块哈希去重窗口
  （`max-seen-hashes`，LRU）、孤儿队列（`max-orphans`）均有上界。
  回退重试耗尽后待重新接纳的哈希记录同样以 `max-seen-hashes` 为上界（LRU），
  重试与重新接纳不会造成去重记录无界增长。
- **崩溃恢复**：仅“完整校验通过并上链”的区块通过追加日志（`storage/FileBlockRepository.java`）
  持久化；未完成重建只存在于内存。重放时崩溃产生的不完整尾部记录会被截断丢弃，
  因此未完成重建不会被误判为已接收，重启后重复通知由已确认区块状态直接去重。

## 配置参数

`application.properties` 前缀 `compact-relay`（见 `config/RelayProperties.java`）：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `short-id-bytes` | 8 | 短标识字节数（64 位 SipHash） |
| `rebuild-timeout-ms` | 2000 | 紧凑重建整体超时，超时回退完整区块 |
| `tx-request-timeout-ms` | 500 | 单次缺失交易补齐请求超时 |
| `max-mempool` | 10000 | 本地交易池容量上界（FIFO 淘汰） |
| `max-seen-hashes` | 4096 | 已见区块哈希去重窗口上界（LRU） |
| `max-orphans` | 64 | 孤儿通知/区块缓存上界 |
| `max-request-retries` | 1 | 补齐请求重试次数，耗尽后回退完整区块 |
| `fallback-request-timeout-ms` | 2000 | 单次完整区块回退请求超时，超时后重试 |
| `max-fallback-retries` | 2 | 完整区块回退请求重试次数（不含首次），耗尽后释放占位允许重新通知 |

新增的回退观测计数（`relay/NodeStats.java`，供测试断言与运行观测）：

- `blockRequests()`：发出的完整区块回退请求总数（含首次与每次重试）。
- `fallbackRetries()`：回退重试次数（不含首次请求）。
- `fallbackExhausted()`：回退重试耗尽、释放占位的区块次数。
- `reacceptedAnnouncements()`：回退失败后被重新接纳、重新进入流程的同一区块通知数量。

## 代码结构

- `model`：`Transaction`、`BlockHeader`、`Block`。
- `protocol`：五类消息（通知、补齐请求/响应、完整区块请求/响应）与按下标携带的 `IndexedTx`。
- `network`：`Network`/`Peer` 抽象与进程内回环实现，支持丢包注入与投递计数。
- `crypto`：SHA-256 txid 与 SipHash-2-4 短标识。
- `pool`：有界本地交易池与短标识候选查找。
- `storage`：已确认区块的追加日志持久化与崩溃重放。
- `relay`：`RelayNode`（事件循环、重建状态机、回退、孤儿、去重）、`ReconstructionSession`、配置与统计。

## 构建与测试

```bash
mvn -o test        # 离线运行全部测试
```

自动化测试（28 个用例）覆盖：缺失交易合并补齐、全内存重建、短标识碰撞歧义、
错误交易内容触发回退、补齐请求超时重试、重建超时、迟到响应去重、并发通知去重、
过期通知丢弃、孤儿通知重放、交易池/去重窗口上界、重启恢复（含日志半条记录截断），
以及新增的两类异常时序：

- **重建期新交易回填**（`InFlightTxBackfillTests`）：在途补齐期间本地新交易到账后无需等待
  响应即上链；已回填槽位在后续超时重试中不再被请求；一笔新交易同时填入多个在途竞争会话；
  迟到补齐响应被安全丢弃、区块只应用一次；回填时短标识歧义仍回退完整区块。
- **回退可靠性**（`FallbackReliabilityTests`）：回退请求被丢弃后的超时重试并最终成功；
  重试耗尽后释放占位、重新通知恢复上链；回退期间重复通知不产生额外请求；迟到完整区块响应
  与重复通知安全丢弃、区块只应用一次。

所有测试基于进程内回环网络，不依赖真实网络或外部服务，稳定可重复。
